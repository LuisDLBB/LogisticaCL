LogisticaCL — Contexto de integración

Documento de coordinación inicial entre Luis y Hans para el sistema logístico de 4N.

Objetivo

Construir un sistema logístico conectado a una solución mayor, utilizando maestros estándar compartidos y un ambiente de pruebas en dev.4n.cl.

Decisión de datos

Se usará una base de datos compartida para varias empresas. Cada tabla que guarde información propia de una empresa deberá incluir tenant_id como campo obligatorio.

  • Las consultas deben filtrar siempre por tenant_id.
  • Las claves únicas deben considerar la empresa, por ejemplo (tenant_id, codigo_cliente).
  • Los índices principales deben comenzar por tenant_id cuando corresponda.
  • Los maestros universales pueden ser compartidos; los configurables por empresa deben incluir tenant_id.
  • Los cambios de estructura se implementarán mediante migraciones versionadas en Git.

Forma de trabajo

  1. Crear una rama desde develop, por ejemplo feature/maestros-estandar.
  2. Implementar el cambio junto con su migración de base de datos, si aplica.
  3. Subir la rama a GitHub y abrir una solicitud de cambio hacia develop.
  4. Revisar e integrar el cambio.
  5. Desplegar develop en dev.4n.cl para probar la integración.
  6. Cuando esté aprobado, integrar develop hacia main.

Coordinación de maestros estándar

Antes de crear o modificar un maestro estándar, acordar nombre de tabla, campos, tipos de datos, claves, relaciones y responsable. El acuerdo debe quedar documentado en el repositorio y aplicarse mediante una migración.

Las claves, contraseñas y otros datos de acceso no deben incluirse en este documento ni en el repositorio. Deben almacenarse como configuración privada del entorno.
